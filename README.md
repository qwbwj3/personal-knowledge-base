# 个人知识库

**把产品资料、工作经验和历史作品，变成 WorkBuddy 随时可以调用的工作资料库。**

为保险经纪人的日常工作设计：查产品规定、比较不同条款、整理客户常见问题，或结合自己的经验写一篇口播稿。你用自然语言提出任务，WorkBuddy 从你授权的资料中查找、阅读，再组织回答。

它是一项安装在 WorkBuddy 中的 Skill。你提供资料，它帮助你建立、维护和使用知识库，不需要自己写代码或维护登记表。

## 它能帮你做什么

| 工作场景 | 使用方式 |
| --- | --- |
| 查产品资料 | 查找等待期、保障责任、免责条件等内容，回答附上资料来源和页码，方便回原文核查。 |
| 比较多份产品 | 围绕同一个问题整理不同产品的规定，区分产品与版本。 |
| 辅助内容创作 | 结合产品事实、业务经验和历史文案，准备口播稿、文章或客户答疑。 |
| 核查已有文案 | 对照知识库检查产品说法，指出缺少依据或需要回看原文的地方。 |
| 持续积累资料 | 新增文件后更新同一个库；遇到版本替换或资料问题，集中说明需要处理的内容。 |
| 浏览自己的知识 | 在 Obsidian 中查看分类、资料全文、主题关联和对应原件。 |

**产品条款用来核对事实，个人笔记和历史文案用来提供经验与表达参考。** 两类资料可以一起使用，但不会把个人解读当成正式产品规定。

## 格式支持不是仅PDF

支持PDF、DOCX、XLSX、CSV、Markdown、文本、HTML与PNG/JPEG/WebP。长截图由当前Agent直接查看原分辨率区域，保存正文和表格，不需要先让OCR通过；Excel保留坐标、公式、已有结果与常见显示格式，需要重算时调用宿主实际可用的表格工具。DOCX复杂版式、Excel嵌图/图表及PPT/PPTX、旧DOC/XLS仍有明确限制。[完整能力与限制](skills/personal-knowledge-base/references/supported-formats.md)。

本次整合包含工作坊待办/路径修复及长图、Excel新能力。发布状态以仓库正式标签和验收记录为准。

## 开始使用

### 1. 安装到 WorkBuddy

把下面这段发给 WorkBuddy：

```text
请帮我安装个人知识库 Skill：
https://github.com/qwbwj3/personal-knowledge-base

使用正式版本 v1.3.0。
请检出该标签，核对并记录它对应的完整提交。

请从 Git 仓库获取，阅读安装说明后完成安装。
需要我授权或操作时，用普通语言告诉我。
安装后告诉我如何开始建立自己的知识库。
```

WorkBuddy 会按安装说明检查所需环境。扫描PDF可按需使用本地OCR；普通图片和长截图优先使用当前Agent的看图能力，不要求先安装OCR模型。想用可视化方式浏览资料，可以同时使用 Obsidian。

### 2. 选一个资料文件夹

可以放入产品条款、产品说明、工作笔记、常见问题和自己写过的内容。已有混放文件夹也可以使用，不必为了建库把所有文件重新命名、搬动一遍。

然后告诉 WorkBuddy：

```text
帮我建立一个知识库，叫“我的业务知识库”。
我会提供资料文件夹的位置，请先和我确认读取范围、
保存位置，以及哪些内容可以交给当前模型处理。
```

如果文件夹有明确用途，也可以补充：

> 这个文件夹专门存产品资料，以后新增到这里的文件也按这个用途处理。

WorkBuddy 会读取资料正文并归类。完成后，你会看到哪些资料已可使用，哪些还有问题，以及是否有需要你决定的版本替换。

### 3. 直接提出工作任务

明确说“调用我的知识库”或“结合我的知识库”，再描述你要完成的事。

**查询规定**

> 调用我的知识库，查一下这款产品的等待期和免责条件，标出资料名称、版本和页码。

**比较产品**

> 调用我的知识库，比较 A、B 两款产品的保障范围和免赔额。分开列出，资料没有写清楚的地方也告诉我。

**准备内容**

> 结合我的知识库，写一条解释医疗险免赔额的口播稿。产品规定以正式资料为依据，表达方式参考我以前的文案。

**检查说法**

> 调用我的知识库，检查下面这段客户答疑。哪些说法有条款支持，哪些需要修改或补充条件？

## 已参加工作坊：更新已有 Skill

不用卸载旧版，不用删除知识库或重新上传已保存的资料。把下面这段交给 WorkBuddy：

```text
请帮我更新个人知识库 Skill：
https://github.com/qwbwj3/personal-knowledge-base

使用正式版本 v1.3.0，核对标签对应的完整提交，按安装说明走更新流程。
保留我已有的知识库、原件、授权设置和个人笔记，不要卸载或删库重建。
更新后核对实际生效版本，再继续处理之前未完成的图片和表格；
已完成且仍有效的资料不要重复处理。
```

Skill更新只更换代码，资料库维护是后续独立步骤。遇到安装目录被占用，WorkBuddy会保留旧版与候选，提示正常退出后续装，不需要手工删目录。已经卸载过Skill的学员，可以先安装新版，再定位仍保留的资料库；不要把旧资料目录当成安装目录覆盖。

## 以后怎么维护

- **新增资料：** 把文件放进已授权的资料文件夹，然后说“我新增了几份产品资料，更新我的知识库”。
- **产品出了新版：** 更新时查看新旧变化，再决定是否采用新版作为依据。
- **一次导入很多文件：** 提前告诉 WorkBuddy 大致数量和大小，让它按批量流程处理；待处理项目分组查看，不用逐份重复对话。
- **想看看资料库：** 说“打开我的 Obsidian 知识库”。
- **某份资料不再使用：** 明确告诉 WorkBuddy 停用哪一份资料。

原文件不会因为建库被改写、移动或删除。更新会复用仍然有效的提取结果；文件级处理中断后可以继续，不必从头处理所有文件。

## 可以放哪些文件

- **文档与表格：** PDF、Word（DOCX）、Excel（XLSX）、CSV。
- **文字与网页文件：** Markdown、TXT、HTML。
- **图片与扫描件：** PNG、JPG、JPEG、WebP，以及扫描版 PDF。普通图片支持直接视觉读取；扫描PDF可按需OCR并复核。

导入前会检查数量、体积和所需环境。遇到读不清的页面，会说明具体问题；需要看图核对时，使用支持图片的会话或由你查看原页，已完成的处理会保留。

## 资料与核查

资料库和原件快照保存在本机。使用在线模型时，经你授权，回答所需的原文片段会提供给当前模型处理；客户隐私和敏感资料请先脱敏。

产品结论提供来源，便于你快速核查。对外发送前，涉及金额、日期、免责和适用条件的内容，请回到原文确认；资料没有覆盖的问题会明确说明。
